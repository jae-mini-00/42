# Philosophers

42 커먼코어 과제로, C언어와 pthread로 구현한 식사하는 철학자 문제(Dining Philosophers Problem)입니다.

## 프로젝트 개요

- **인원:** 개인 프로젝트
- **핵심 목표:** 여러 철학자(스레드)가 포크(공유 자원)를 두고 경쟁하는 상황에서, 데드락과 기아(starvation) 없이 안전하게 동작하는 동시성 프로그램 구현

## 주요 구현 내용

### 데드락 방지
- 모든 철학자가 동시에 포크를 집으려 들면 서로가 서로의 포크를 기다리며 영원히 멈추는 데드락이 발생할 수 있음
- 철학자 스레드를 한 번에 모두 생성하지 않고, **짝수 인덱스 철학자를 먼저 생성한 뒤 짧은 지연을 두고 홀수 인덱스 철학자를 생성**하는 방식으로 스레드 시작 시점을 의도적으로 어긋나게 만들어, 모든 철학자가 동시에 포크를 집으려 경쟁하는 상황 자체를 회피
- 포크를 집을 때는 `pthread_mutex_lock`으로 한 번에 한 철학자만 특정 포크를 사용하도록 제어하고, 실패 시 짧은 대기 후 재시도하는 방식으로 접근

### 죽음(기아) 감지 — 감시 스레드 없는 분산형 구조
- 별도의 감시 전담 스레드를 두지 않고, **각 철학자 스레드가 스스로 자신의 마지막 식사 시각(`last_eat_time`)을 기준으로 죽음 여부를 판단**하는 구조로 구현
- 포크를 기다리는 동안, 그리고 잠을 자는 동안(`ft_msleep`) 주기적으로 `check_die`를 호출해 자신이 `time_to_die`를 초과했는지 스스로 체크
- 죽음을 감지한 철학자는 공유된 `finish_flag`를 뮤텍스로 보호하며 켜고, 다른 모든 철학자 스레드는 각자의 루프 시작 지점에서 이 플래그를 확인해 종료
- 이를 통해 "누가 누구를 감시한다"는 중앙 감시 구조 없이도, 각자가 자기 상태를 스스로 책임지고 결과만 공유하는 방식으로 동시성 문제를 해결

### 출력 동기화
- 여러 스레드가 동시에 `printf`를 호출하면 출력이 뒤섞일 수 있어, 별도의 출력 전용 뮤텍스(`print_mutex`)로 로그 출력을 보호

## 기술 스택

- 언어: C
- 동시성: pthread, mutex

## 배운 점

여러 스레드가 공유 자원(포크)을 두고 경쟁하는 상황에서, 스레드가 시작되는 시점 하나만 조정해도 데드락 자체를 원천 차단할 수 있다는 것을 확인했습니다. 또한 "감시자가 전체를 지켜본다"는 중앙집중적인 방식이 아니어도, 각 스레드가 자기 상태를 스스로 판단하고 결과만 공유하는 분산형 구조로도 문제를 해결할 수 있다는 것을 배웠습니다.
